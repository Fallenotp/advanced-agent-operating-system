# Job description fields — Step 1

One page, plain English. Fill in every field before the agent starts.

1. **Role** — one line: what it is, e.g. "Review responder for your business".
2. **Mission** — one sentence: what success looks like.
3. **Owner** — the owner. He checks it. A person owns the outcome; the agent does not answer for the result.
4. **Responsibilities** — 3 max, each with a frequency.
5. **Steps** — the step-by-step, in order, with the why for any step that is not obvious. Paste a video link or written guide here if one exists.
6. **Deliverable + definition of done** — exact format, and how the owner will know it is right. Include 1–2 examples of good output and 1 of bad. Include test examples the agent must pass.
7. **Sources of truth** — where facts come from; if it is not there, flag it, do not guess.
8. **Tools & access** — what it can read, what it can change, what it can never touch.
9. **Green / amber / red** — acts alone / asks first / hands to the owner. Nothing public, involving money, or irreversible without the owner's yes.
10. **Schedule + report** — when it runs, and when/how it reports back for review.
11. **Correction log** — where fixes go, so the same mistake is never fixed twice. See `../../../docs/step-4-corrections-log-example.md`.

## First-job test

A good first job is recurring, written output, checkable in under 5 minutes. Examples: drafting replies to new reviews (draft-only, owner approves), or a weekly research brief. Not anything that sends, pays, or publishes on its own.

## What a corporate job description drops, and what an agent version adds

A corporate job description assumes a human will fill gaps with judgement; an agent fills gaps with guesses, so the gaps have to be written down. Drop salary, qualifications, and working conditions. Add deliverable format, sources of truth, tools and permissions, in-scope / out-of-scope plus escalation, definition of done, test examples, correction log, schedule/trigger, and a review cadence.
